# 小程序商品、角色、手机号与地址体验设计

## 目标

- 商品编辑提交必须给出进行中、成功或失败的明确反馈，并能正确提交品类属性对象。
- 采购商只有在供应商或司机申请审核通过后，才能看到并切换到对应角色。
- 所有用户填写的中国大陆手机号统一限制为 11 位，并由前后端共同校验。
- 地址页把省、市、区合并成一个三级联动选择项，详细地址单独填写。

## 设计

商品 DTO 将 `attrValues` 按对象校验；小程序请求层完整显示后端错误，商品页增加防重复提交状态。角色列表从用户已获批的 `roles` 派生，切换失败时不再本地强制切换；审核通过时后端同步把角色写入用户角色集合。手机号使用共享正则规则，关键 DTO 和所有用户输入入口同时约束。地址仍保留现有省、市、区数据库字段以兼容历史数据，但页面通过一个 `region` 选择器一次完成三级选择。

## 验收条件

1. `attrValues` 为对象的商品更新 DTO 校验通过，数组以外的错误 SKU 数据仍被拒绝。
2. 商品提交时按钮显示“提交中”，失败显示具体原因，成功后返回。
3. 未获批角色不显示；后端拒绝切换时当前角色不变；审核通过后角色写入用户记录。
4. 登录、注册、入驻申请、地址和运营后台新增用户均拒绝非 11 位大陆手机号。
5. 地址新增和编辑页面只有一个“所在地区”选择项，选择后保存到原有三个字段。
